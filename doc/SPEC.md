# 项目规格说明书（SPEC）

---

## 1. 项目概述

### 1.1 一句话描述
中文意图分类 API 服务，输入用户指令 → 输出 12 类意图标签，支持 4 种算法对比。

### 1.2 目标用户
学习 NLP 意图分类的开发者，需在本地环境快速搭建并测试不同模型的效果差异。

### 1.3 核心约束
- 全部本地可运行，不依赖外部付费服务
- 强制类型标注 + Pydantic 数据校验
- 前端零构建工具（纯静态 HTML/CSS/JS）
- 配置集中管理（`config.py` 单文件）

### 1.4 先做 vs 不做

| 先做（v1 范围内） | 不做（明确排除） |
|---|---|
| 数据集加载与管理 | 用户认证 / API 鉴权 |
| 正则匹配分类 | 限流（Rate Limiting） |
| TF-IDF + SVM 训练与推理 | 模型热加载 |
| BERT 训练与推理 | Docker 容器化 |
| LLM 动态 Few-shot 分类 | 生产环境部署 |
| 前端交互测试界面 | Kubernetes / CI-CD |
| 统一 REST API（4 个 endpoint） | 知识库问答（RAG）模块 |
| 日志与异常捕获 | 多语言分类支持 |
| 请求/响应统一 Schema | 流式响应 |

## 3. 架构设计

### 3.1 整体架构

```
┌──────────────────────┐          ┌─────────────────────────────┐
│    Web 前端           │  HTTP    │      FastAPI 后端            │
│  (纯静态 HTML/CSS/JS) │ ◄──────► │                            │
│                      │   CORS   │  GET  /         健康检查    │
│  文本输入框            │          │  POST /v1/text-cls/regex    │
│  模型选择卡片          │          │  POST /v1/text-cls/tfidf    │
│  结果展示区            │          │  POST /v1/text-cls/bert     │
│  性能指标             │          │  POST /v1/text-cls/gpt      │
└──────────────────────┘          └───────────┬─────────────────┘
                                              │
                    ┌─────────────────────────┼─────────────────────────┐
                    │          model/          │                         │
                    │  regex_rule ──┬──────────┤                         │
                    │  tfidf_ml  ───┤  统一接口 │                         │
                    │  bert.py   ───┤          │                         │
                    │  prompt.py ───┘          │                         │
                    └─────────────────────────┘                         │
                    ┌─────────────────────────────────────────────┐     │
                    │   config.py  |  data_schema.py  |  logger.py│     │
                    └─────────────────────────────────────────────┘     │
```

### 3.2 模型对比

| 模型 | 类型 | 速度(单条) | 相对精度 | 依赖 |
|---|---|---|---|---|
| Regex | 关键词规则 | <10ms | 低 | 无 |
| TF-IDF + LinearSVC | 传统 ML | <50ms | 中 | scikit-learn, jieba |
| BERT (bert-base-chinese) | 深度学习 | ~200ms (CPU) | 高 | torch, transformers |
| LLM (Qwen/Ollama) | 大语言模型 | ~1-2s | 高 | openai SDK |

### 3.3 LLM 推理策略

使用动态 Few-shot 方式：
1. 输入文本 → TF-IDF 向量化
2. 与训练集计算余弦相似度 → 取 Top-10 最相似样本
3. 拼接为 "文本 -> 标签" 格式作为 prompt 中的参考例子
4. 提交到 LLM 获取分类结果

参数：`temperature=0`（确定性问题），`max_tokens=64`

## 4. 前端规格

### 4.1 页面布局
1. 头部：项目标题 + 副标题
2. 输入区：文本输入框 + 示例按钮（播放音乐/查询天气/设备控制/日程查询）
3. 控制区：模型选择（4 个卡片，单选）+ 操作按钮（开始分类/清空结果）+ 后端状态
4. 结果区：展示分类结果、输入文本、响应时间
5. 性能指标区：响应时间、相对精度、相对成本

### 4.2 交互流程
1. 页面加载 → 检测后端健康状态（`GET /`）
2. 用户输入文本或点击示例按钮
3. 选择模型 → 点击"开始分类"
4. 显示 loading 动画 → 接收结果 → 渲染结果卡片
5. Ctrl+Enter 快捷触发分类

### 4.3 技术约束
- 纯静态文件，不需要任何构建工具
- 通过 fetch API 调用后端
- 后端必须开启 CORS

---

## 5. 非功能需求

- **日志**：INFO 级别记录请求，ERROR 级别记录异常堆栈
- **异常处理**：所有业务异常在模型层捕获，API 层不关心模型内部细节
- **并发**：FastAPI 异步原生支持，多 worker 可扩展
- **状态管理**：无状态服务，不保存用户会话
