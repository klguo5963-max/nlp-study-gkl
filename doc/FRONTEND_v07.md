# v0.7 前端完整版 · 开发规范

## 概述

v0.7 将前端从目前的"单模型调用"升级为"全模型对比平台"。
分为 3 个独立可验证的子轮次，严格执行**每轮一改、改完即验、通过才进下一轮**。

---

## 总原则

1. **不能动已有的后端 endpoint**。`POST /v1/text-cls/{regex|tfidf|bert|gpt}` 的签名、参数、响应结构不允许修改。
2. **不能动已有的 HTML 结构**。`index.html` 中现有的 id / class 名称不能改（`js` 和 `css` 依赖它们）。
3. **新增功能只新增文件，或只修改 `script.js` / `style.css`**，不新增第三方库。
4. **每轮完成后必须做回归测试**：老功能（选一个模型 → 输入文本 → 看到结果）仍然能正常工作。

---

## 轮次 1/3：修复多模型调用逻辑

### 目标

当前 `script.js` 的 `displayResult` 函数是一个通用展示函数，看起来应该支持 4 个模型。
但实际验证中发现选 BERT/GPT 模型后前端调用的是对应 endpoint，结果能正常展示——只是尚未经过真正的端到端测试。

**本轮的真正任务**：确认并修复所有模型的前端调用链路都能正常工作，
并增加分类结果的标签颜色（不同类别的 label 用不同颜色高亮）。

### 改动范围

只改 `frontend/script.js`：
- 不需要改 endpoint 调用逻辑（当前 `API_ENDPOINTS` 和 `processText` 已经支持多模型）
- 增加一个 `CATEGORY_COLORS` 映射表，为 12 个类别赋予不同的颜色
- 修改 `displayResult` 函数，在结果区域中给分类结果 label 加上对应颜色的 badge
- 增加异常情况处理：请求成功但 `error_msg` 不为 "ok" 时展示警告

### 具体实现要求

1. `CATEGORY_COLORS` 对象定义 12 个类别到颜色的映射（颜色使用 CSS 类，不直接写色值在 JS 中）
2. 在 `style.css` 中新增 `.badge-alarm`、`.badge-weather` 等 12 个样式类
3. 在结果卡片中分类结果显示为带有颜色 badge 的标签（而不是普通文本）
4. 后端返回的 `classify_result` 如果是数组，每个元素独立显示为一个 badge
5. 如果响应中 `error_msg !== "ok"`，在结果卡片的上方显示一个黄色警告条

## 轮次 2/3：一键全模型对比模式

### 目标

在当前单模型选择的基础上，增加一个"全部对比"功能按钮。
点一次按钮，自动调用 4 个 endpoint，将结果并排展示。

### 改动范围

- `frontend/index.html`：在"开始分类"按钮旁增加一个"全部对比"按钮（id: `compareBtn`）
- `frontend/script.js`：新增 `compareAllModels` 逻辑
- `frontend/style.css`：新增对比视图的样式

### 具体实现要求

1. 新增按钮"全部对比"，放在"开始分类"右侧，样式为紫色渐变
2. 点击后同时发送 4 个异步请求（用 `Promise.all`），不阻塞 UI
3. 加载期间显示 4 个并排的 loading 骨架屏（每个模型一个）
4. 每个请求完成后独立更新对应的骨架屏为结果卡片
5. 结果卡片改为 2×2 网格布局（4 个模型各占一格）
6. 每个卡片顶部显示模型名称 + 响应时间
7. 如果某个模型请求失败，对应卡片显示错误状态，不影响其他模型
8. 清空按钮同时清理对比模式的结果

### 验证清单

| # | 操作 | 预期结果 |
|---|---|---|
| 1 | 点击"全部对比" | 4 个骨架屏同时出现，loading 动画在各自卡片内 |
| 2 | 等待请求完成 | 4 个骨架屏逐个变为结果卡片，响应时间各不相同 |
| 3 | 正则卡片显示多个类别（如"播放"） | 多个颜色的 badge |
| 4 | 停止后端后点"全部对比" | 4 个卡片都显示错误状态 |
| 5 | 对比完成后点清空 | 回到初始状态 |
| 6 | 对比完成后用 Ctrl+Enter | 触发的是选中模型的单次分类，不触发对比 |

## 轮次 3/3：性能指标面板

### 目标

在结果区域下方增加一个性能指标对比面板，展示本次分类中 4 个模型的响应时间、相对精度估计和相对成本。

**注意**：这里展示的不是真实精度指标（无法在推理时实时计算），而是基于模型基准的**相对参考值**。
数据源是 `MODEL_BENCHMARKS` 中的预设值，结合本次请求的实际响应时间。

### 改动范围

- `frontend/index.html`：在结果区下方增加一个"性能对比"区域
- `frontend/script.js`：新增 `displayBenchmarks` 函数
- `frontend/style.css`：新增面板样式

### 具体实现要求

1. 只有执行过"全部对比"后才显示性能面板（单模型分类不触发）
2. 面板标题为"⚡ 模型性能对比"
3. 面板包含一张表格，4 行 4 列：
   | 模型 | 响应时间 | 预估精度 | 开销 |
   |---|---|---|---|
   | 正则匹配 | xx ms | 中 | 低 |
   | TF-IDF | xx ms | 高 | 低 |
   | BERT | xx ms | 非常高 | ~~中~~ |
   | GPT | xx ms | 非常高 | ~~高~~ |
4. "响应时间"列使用本次请求的实际值（`data.classify_time * 1000`）
5. "预估精度"列使用 `MODEL_BENCHMARKS` 中的 accuracy 范围描述（<60→低，60-80→中，80-90→高，>90→非常高）
6. "开销"列使用 `MODEL_BENCHMARKS` 中的 cost 范围描述（<=2→低，<=5→中，>5→高）
7. "响应时间"列使用彩色文字高亮（最优值绿色，最差值红色）
8. 表格隔行变色，易于阅读

### 验证清单

| # | 操作 | 预期结果 |
|---|---|---|
| 1 | 点"全部对比"完成之后 | 性能面板显示在结果下方 |
| 2 | 面板中有 4 行数据 | 每个模型一行 |
| 3 | 响应时间显示实际值 | 正则 < TF-IDF < BERT < GPT 的顺序（ms 值递增） |
| 4 | 最优时间行显示绿色 | 最慢的显示红色 |
| 5 | 单模型分类后 | 性能面板不出现 |
| 6 | 清空后 | 性能面板消失 |

## 附录：当前前端文件引用关系

```
index.html
  ├── style.css        (现有，无构建工具)
  ├── script.js        (现有，ES6+ 语法，直接执行)
  └── Font Awesome 6   (CDN)
     ├── Google Fonts (Inter)
     └── fa-solid.css  (CDN)

script.js 中引用的全局对象/函数：
  API_BASE              → "http://localhost:8000"
  API_ENDPOINTS         → { regex, tfidf, bert, gpt }
  MODEL_BENCHMARKS      → { regex, tfidf, bert, gpt } 每项含 time/accuracy/cost/name/icon
  processText()         → 核心分类函数
  displayResult()       → 渲染结果
  clearResults()        → 清空
  checkAPIStatus()      → 健康检查
  escapeHtml()          → HTML 转义
  showError()           → 错误提示
```
